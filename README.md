# PAUSE

**넘기기 전에, 남겨보세요.** YouTube 롱폼 영상을 시청하고 메모·성찰을 기기에 저장하는 Chrome Manifest V3 확장 프로그램입니다. 외부 서버로 기록을 전송하지 않습니다.

## 현재 준비 상태

Task 001의 기반 구현에 Task 002 안정화를 추가했습니다. 자동 테스트와 빌드는 실행했지만, **실제 데스크톱 Chrome + YouTube 수동 검증은 모두 검증 대기**입니다. 자동 테스트의 jsdom 영상·저장소 mock 결과를 Chrome 통과로 해석하지 마세요. 절차와 기록 양식은 [10분 수동 검증 가이드](docs/manual-chrome.md)에 있습니다.

## 빌드와 설치 산출물

필요 도구: Node.js 22.12+ 또는 24 LTS, npm, ZIP 포장 시 Python 3.

```sh
npm ci
npm test
npm run build
npm run package:chrome
```

`build`는 타입 검사와 popup/content script 프로덕션 빌드입니다. `package:chrome`은 다시 빌드한 뒤 다음 파일을 생성하고 ZIP 무결성과 manifest의 참조 파일을 확인합니다.

- `dist/`: Chrome에 로드할 폴더. 바로 아래에 `manifest.json`, `content.js`, `popup.html`, `assets/`가 있습니다.
- `dist/PAUSE-BUILD.json`: 빌드 커밋, 미커밋 변경 여부, 빌드 시각, Node 버전, lockfile 해시. 검증한 버전 식별용이며 메모/비밀값은 포함하지 않습니다.
- `artifacts/pause-chrome-0.1.0-task002.zip`: **ZIP 바로 안에 manifest.json이 있는** 설치 패키지.
- `artifacts/SHA256SUMS`: 위 ZIP의 SHA-256.

### PC로 가져오는 방법

클라우드의 `/workspace/pause/dist` 또는 `/workspace/...zip` 경로는 **사용자 PC에서 열 수 있는 다운로드 URL이 아닙니다**. 이 문서의 로컬 파일 링크도 배포 링크가 아닙니다. GitHub 소스의 **Code → Download ZIP**에는 빌드 산출물이 없습니다.

권장 방법은 GitHub Actions 아티팩트입니다. 이 브랜치의 `.github/workflows/chrome-build.yml`은 push/PR에서 테스트와 빌드를 실행하고 `dist/`를 `pause-chrome-task002`라는 아티팩트로 14일간 보관합니다. 릴리스나 운영 배포는 만들지 않습니다.

1. GitHub에서 이 저장소의 **Actions → Chrome validation build**를 엽니다. 작업 브랜치 `feature/pause-longform-mvp`와 최신 커밋의 실행을 선택합니다.
2. 테스트와 빌드, 업로드 단계가 성공했는지 확인합니다. **성공한 원격 실행을 확인하기 전에는 다운로드 가능한 아티팩트가 있다고 간주하지 마세요.** Actions 비활성화·워크플로 파일 push 권한 부족·용량 제한 시 아티팩트가 생기지 않을 수 있습니다. `workflow_dispatch` 버튼은 워크플로가 기본 브랜치에 없으면 표시되지 않을 수 있습니다.
3. 실행 상세의 **Artifacts → pause-chrome-task002**를 클릭해 `pause-chrome-task002.zip`을 PC에 다운로드합니다. GitHub 로그인과 저장소 읽기 권한이 필요합니다. 만료 시 새 push로 다시 빌드하거나 아래 PC 빌드를 사용합니다.
4. 예를 들어 PC의 `Downloads/PAUSE/task002/`에 압축을 풉니다. **그 폴더 바로 아래에 `manifest.json`이 있는지 확인**합니다. GitHub Actions ZIP은 dist 내용 자체를 담으므로 내부 ZIP을 다시 풀 필요가 없습니다.
5. 클라우드 파일 다운로드 기능이 별도로 제공된다면 `artifacts/pause-chrome-0.1.0-task002.zip`을 내려받아 같은 방식으로 압축을 풀 수 있습니다. 이 작업 환경에서는 파일 업로드/다운로드 URL 발급 도구가 제공되지 않아 해당 링크를 발급하지 않았습니다.

원격 Actions 사용이 막힌 경우, PC에서 GitHub 소스를 받아 직접 빌드할 수 있습니다. 공개 릴리스 승인은 필요하지 않습니다.

```sh
git clone --branch feature/pause-longform-mvp https://github.com/yoonjae0707/pause.git
cd pause
npm ci
npm test
npm run build
```

이 경우 PC의 `pause/dist/`를 사용합니다. Python이 없어도 `build`까지는 가능합니다.

### 데스크톱 Chrome 설치와 설치 확인

1. ZIP이라면 먼저 압축을 풉니다. Chrome은 ZIP 파일을 직접 로드하지 않습니다. 로드한 폴더는 삭제하거나 이동하지 마세요.
2. Chrome 주소창에 `chrome://extensions`를 입력하고 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드**를 눌러 `manifest.json`이 바로 있는 폴더를 선택합니다. Actions 다운로드 예시는 `Downloads/PAUSE/task002/`, PC 빌드는 `pause/dist/`입니다. 소스 루트나 `assets/`를 선택하지 마세요.
4. 목록에서 PAUSE 0.1.0이 활성 상태이고 오류가 없는지 확인합니다. 도구 모음의 확장 프로그램 메뉴에서 PAUSE popup을 열어 두 설정과 기록 수를 확인합니다.
5. 이미 열려 있던 `https://www.youtube.com/watch?v=...` 탭을 새로고침합니다. PAUSE 사용을 켠 상태에서 `PAUSE Notes` 버튼이 보이는지 확인합니다.
6. 새 빌드로 교체할 때 기존 확장 프로그램의 **새로고침**을 누르고 YouTube 탭도 새로고침합니다. 기록을 유지하려면 확장 프로그램을 삭제해 재설치하지 마세요. 설치한 폴더의 `PAUSE-BUILD.json` 커밋을 기록합니다.

`npm run dev`는 popup UI 개발용입니다. 확장 프로그램의 빌드/설치와 YouTube 테스트를 대체하지 않습니다.

## 시청·성찰 정책

- 추적/UI는 `/watch?v=...`에서 활성화합니다. 홈 → watch SPA 이동을 위해 content script 주입 대상은 `https://www.youtube.com/*`입니다.
- **벽시계 기준** 실제 재생 시간이 30초 이상이며 영상 길이의 70% 이상일 때 종료 성찰을 표시합니다. 100초 영상을 2배속으로 50초 시청하면 70초 기준을 충족하지 않습니다. 고유 구간 커버리지 대신 재시청 시간도 누적합니다.
- seek와 속도에 맞지 않는 위치 도약은 제외합니다. SPA 이동 중 이벤트를 해제하고, video 교체/소스 로드에서 기준점을 초기화합니다. 같은 바인딩의 이벤트 리스너를 중복 등록하지 않습니다. 성찰 중에는 시청 시간을 누적하지 않습니다.
- 동일 영상의 종료 개입은 탭의 content script 수명 동안 한 번입니다. 새로고침 시 시청 누적/개입 상태만 초기화되고 저장 메모/초안은 남습니다. 라이브·무한 길이는 종료 성찰 대상이 아닙니다.
- 성찰은 즉시 저장 가능하며, 기록 없이 건너뛰기는 5초 뒤 가능합니다. 불이익이 없습니다.
- 개입 중 일반 클릭으로 요청한 동일 사이트 watch/shorts 링크 한 개를 완료 후 이동합니다. 수정키/새 탭 이동은 가로채지 않습니다. 개입이 일시정지시킨 다른 영상이 여전히 현재 영상이면 완료 후 재개를 시도합니다. 이미 일시정지된 영상이나 종료된 원본을 임의로 재생하지 않습니다. 명시적인 링크 요청이 있으면 그 이동을 우선합니다. 브라우저가 재개를 거절하면 직접 재생 버튼을 눌러야 합니다.

## 데이터·동시 편집·권한

`chrome.storage.local`의 `pause:v1:` 개별 키를 사용합니다. `VideoRecord`, `TimestampNote`, `Reflection`, `ShortsSession`, `UserSettings` 모델이 있습니다. 쇼츠 UI, Library, 서버, 로그인, AI, 휴식 알림은 없습니다. 권한은 `storage` 하나입니다.

- 첫 비공백 입력 시점의 영상 ID·제목·URL·재생 시각을 초안에 캡처합니다. 저장 중 SPA 이동이 발생해도 다른 영상 제목으로 기록하지 않습니다.
- 저장 메모·영상 메타데이터·초안 비우기를 하나의 storage.set 요청으로 보냅니다. 실패 시 초안을 남기고 오류를 안내합니다. 별도 트랜잭션/분산 잠금을 구현한 것은 아닙니다.
- **동일 영상 초안을 여러 탭에서 편집하면 마지막 저장 우선이며, 다른 탭의 초안을 덮어쓸 수 있습니다.** 입력 중인 다른 탭의 로컬 UI는 자동으로 병합/갱신하지 않습니다. 한 탭에서 메모를 저장하며 초안을 비우는 것도 마지막 쓰기입니다. 탭마다 다른 내용이 있으면 각자 저장 메모로 확정한 뒤 이동하세요. 동일 영상 메타데이터와 설정에도 마지막 저장 우선이 적용됩니다. 서로 다른 저장 메모는 고유 ID를 사용합니다.
- 초안 쓰기는 비동기입니다. 입력 직후 즉시 새로고침/탭 종료하면 미완료 쓰기가 유실될 수 있습니다. 중요한 내용은 **메모 저장 후 목록에 표시된 것을 확인**하세요. 저장 실패/용량 초과 시 내용을 복사해 보관하고 다시 시도하세요.
- 확장 프로그램 삭제 시 기록도 삭제됩니다. 현재 내보내기/백업/삭제 관리 UI는 없습니다.

## 알려진 한계와 광고 처리 결정

YouTube 내부 자동재생 예약, 키보드 이동, 브라우저 뒤로/앞으로 및 전체 페이지 이동을 모두 차단하지 않습니다. 다음 URL로 이미 넘어갔을 수 있으며 새 video를 일시정지·재개하는 방식은 최선 노력입니다. 전체 페이지 탐색은 메모리에 있는 성찰/보류 이동 요청을 잃을 수 있습니다. 브라우저 타이머 제한과 DOM 변경에도 영향을 받습니다. 전체화면은 YouTube 플레이어 밖의 오버레이가 보이지 않을 수 있으므로 직접 확인해야 합니다.

**HTML5 video 이벤트만으로 광고를 신뢰성 있게 구분할 수 없습니다.** 현재 구현은 광고를 제외한다고 주장하지 않습니다. `#movie_player.ad-showing` 같은 내부 클래스는 진단 힌트일 뿐 안정적인 공개 API가 아니므로 추측으로 시청 시간을 빼지 않습니다. 광고가 같은 video/영상 ID를 사용하면 시간 누적 또는 광고 ended가 성찰 조건에 영향을 줄 수 있습니다. 소스 교체 시 기준점 초기화는 이 문제 전체를 해결하지 않습니다.

수동 검증에서는 광고 유무를 반드시 기록하고, 광고가 없는 영상 테스트와 분리하세요. 광고가 나타나지 않으면 그 항목은 통과가 아니라 검증 대기입니다. 광고 환경의 오개입이 확인되면 성찰 설정을 끄고 Notes만 사용하는 것이 현재 대안입니다. 신뢰할 수 있는 식별 근거를 확보하기 전까지 공개 준비 완료로 판단하지 않습니다.

## HOTFIX-002: 종료 성찰 진단과 Chrome 재시험

진단은 기본 꺼짐입니다. **popup → 개발용 진단 로그**를 켠 뒤 YouTube 개발자 도구 Console에서 **Info 표시 + Preserve log(로그 보존)**를 켜고 `[PAUSE diagnostic]`으로 필터링하세요. 영상 제목·메모·계정·비밀값은 기록하지 않습니다. 영상 ID와 재생 수치는 진단에 포함됩니다. 테스트 후 popup에서 진단을 끄세요. 로그는 저장소/서버에 수집하지 않고 해당 탭 콘솔에만 출력합니다.

1. 설치는 위 Actions 아티팩트 절차를 사용합니다. 빌드 번호는 여전히 0.1.0이므로 `PAUSE-BUILD.json`의 커밋을 확인하세요. 확장 프로그램과 YouTube 탭을 모두 새로고침합니다. 원격 Actions 성공/아티팩트 생성은 이 작업에서 확인하지 못했습니다.
2. 자동재생을 끄고, 광고 없는 `/watch`의 **1~2분 영상**을 새로고침 후 **1배속·탭 활성·seek 없이 처음부터 끝까지** 재생합니다. PAUSE와 종료 성찰 설정이 켜져 있어야 합니다. 메모 초안을 먼저 입력해 종료 후에도 유지되는지 확인하세요.
3. 정상 로그 흐름은 `sample`의 watched 증가 → `ended`의 `reason: eligible` → `intervention-start` → `overlay-mounted`입니다. ratio는 벽시계 누적/영상 길이이며 최소 0.7, watched는 최소 30초여야 합니다. 화면은 한 번만 나타나고, 5초 이전 저장 가능/건너뛰기 불가, 5초 후 기록 없이 건너뛰기 가능해야 성공입니다.
4. 새로고침해 다시 누적을 초기화하고 자동재생을 켠 상태/재생목록에서 반복합니다. `spa-start`, `binding-boundary`가 `ended`보다 먼저 오는지 확인하세요. 원본 ID로 성찰이 뜨고 다음 영상이 정지되는지 확인합니다. 완료 후 다음 영상 재생 또는 수동 재생이 가능해야 합니다. 이 경로를 실제로 보지 못했으면 검증 대기입니다.
5. 광고가 보이면 `adHint`와 `source-reset` 전후 watched/duration을 함께 기록하세요. 광고 힌트는 추정용이며 광고 시간 제외 기능이 아닙니다. 광고 오개입 또는 종료 누락은 별도로 실패 기록합니다. 비활성 탭/버퍼링/seek 시험은 기본 정상 종료 시험과 분리하세요.
6. Console의 PAUSE 로그 행만 선택해 복사합니다. **전체 Console/HAR/페이지 객체를 통째로 공유하지 마세요.** 진단 시작부터 종료/SPA 이후까지의 JSON 행과 Chrome 버전, 빌드 커밋, 자동재생/광고 여부를 함께 전달하세요.

해석:

- `under-30s` / `under-70-percent`: 정책 미달. sample의 watched와 seeking/source-reset을 확인합니다. 버퍼링 중 시간이 누적되지 않는 것은 정상입니다. 2배속 영상은 길이의 70% 벽시계 조건을 충족하지 못할 수 있습니다.
- `unknown-duration`: 메타데이터가 없거나 라이브/무한 길이입니다.
- `not-at-end`: 이동 시 종료 증거가 부족합니다. 충분히 봤다는 이유만으로 중도 이동을 종료로 간주하지 않습니다.
- `suspended` / `already-handled`: 기존 개입 중이거나 이 탭에서 이미 처리한 영상입니다. 새로고침 후 별도 시험하세요.
- `intervention-rejected`: 설정 비활성/기존 overlay 활성. 거부 시 처리 완료를 확정하지 않도록 수정했습니다.
- `intervention-start`는 있지만 `overlay-mounted`가 없음: React 표시 경로 실패 가능성. Console 오류를 함께 기록하세요.
- `overlay-mounted`는 있지만 화면이 안 보임: 전체화면/표시 레이어 문제 가능성. 전체화면을 나와 확인하세요. mount 로그만으로 실제 표시 통과를 판정하지 않습니다.
- 종료 로그 없이 `spa-start`/`binding-change`만 있음: YouTube가 ended 전에 이동했거나 요소를 교체했을 가능성. 이전 sample의 position/duration을 확인하세요.

확인된 코드 결함은 SPA 전환/요소 해제 시 원본 종료 확인 누락, 그리고 UI가 거부한 개입까지 handled 처리하는 경로입니다. 사용자 환경에서의 원인은 아직 미확정입니다. 종료 경합 보완은 원본의 `ended` 또는 **마지막 관측 위치가 끝에서 0.25초 이내이고 seeking 중이 아닌 경우**에만 적용합니다. 30초·70% 기준은 변경하지 않았습니다. 끝에서 0.25초 이내의 수동 이동을 종료로 추정할 가능성이 있고, 더 이른 자동 전환이나 sample 자체가 없는 경우는 여전히 놓칠 수 있습니다. 광고 식별은 공개 API 없이 확정할 수 없어 추측으로 누적 시간을 제외하지 않습니다.

HOTFIX-002 이후 사용자 데스크톱 Chrome에서 종료 성찰 표시 성공이 보고되었습니다. BUGFIX-001은 아래 변경을 추가하며, 이번 빌드의 실제 Chrome 회귀 검증은 대기입니다.


## BUGFIX-001: Notes 입력과 최초 시각

- Notes·성찰의 input/textarea/contenteditable 키는 window capture에서 `composedPath()`로 PAUSE Shadow DOM 내부 편집 영역인지 확인하고 keydown/keypress/keyup 전파만 중단합니다. Space·숫자·IME·편집/복사 단축키의 기본 입력 동작은 취소하지 않습니다. Tab은 기본 포커스 이동과 기존 성찰 포커스 트랩을 유지합니다. 버튼/영상 등 편집 영역 밖은 변경하지 않습니다. 마운트 시 등록하고 언마운트 시 해제합니다.
- 단순 열기·클릭·포커스·공백만 입력은 시각을 캡처하지 않습니다. 첫 비공백 입력(붙여넣기·IME 입력 포함)에서 영상 메타데이터와 재생 위치를 고정합니다. 이후 재생·seek·저장 지연·초안 복원은 시각을 바꾸지 않습니다. 전부 삭제해 빈 문자열이 되거나 저장이 성공하면 새 메모로 초기화합니다. 이미 캡처한 메모를 공백만 남기도록 편집하면 기존 캡처는 유지됩니다.
- 새 메모의 `timestampSeconds`는 영상 내 최초 입력 위치이며 기존 표시/탐색과 호환되는 `seconds`에도 같은 값을 저장합니다. `createdAt`은 저장 시각입니다. 기존 저장 메모는 다시 쓰거나 변환하지 않습니다.
- 초안 텍스트와 `draftCapture`는 한 번의 storage.set으로 저장합니다. 기존 문자열 초안도 그대로 읽습니다. 최초 시각이 없는 기존 초안 또는 첫 입력 당시 video가 미준비/재생 시각이 유효하지 않은 경우, 현재 시각이나 0초를 임의로 넣지 않습니다. 저장을 거부하고 내용을 복사한 뒤 영상을 준비하고 완전히 비워 다시 작성하도록 안내합니다. 실패한 저장은 초안과 캡처를 유지합니다. 다중 탭의 마지막 쓰기 우선 정책과 비동기 쓰기 완료 전 탭 종료 위험은 그대로입니다.
- HOTFIX-002의 controller/tracker/성찰 5초 정책은 수정하지 않았습니다. 이전 28개를 포함한 자동 회귀를 실행하며, 실제 Chrome 입력/IME 동작은 아래 절차로 별도 확인해야 합니다.

### 이번 빌드의 Chrome 재시험 (검증 대기)

1. Actions의 이번 커밋 빌드 아티팩트를 받아 기존 확장 프로그램 폴더를 교체하고 확장 프로그램·YouTube 탭을 모두 새로고침합니다. 원격 Actions 실행 성공 여부는 이 작업에서 확인하지 못했습니다.
2. 재생 중 Notes를 열고 `안녕하세요 123 456`을 입력합니다. Space·0~9로 재생/탐색이 작동하지 않고 텍스트만 입력되어야 합니다. Backspace·Enter·방향키·Ctrl+A/C/V(macOS는 Cmd도)·Esc·한글 IME 조합/확정을 확인합니다. 성찰 입력창에서도 동일하게 확인하세요. 입력 밖 영상으로 포커스를 옮기면 Space/숫자 탐색이 정상이어야 합니다. YouTube가 먼저 등록한 window capture 리스너까지 이미 실행된 경우에는 이 방식으로 되돌릴 수 없으므로 증상이 남으면 실패로 기록합니다.
3. 5분 이상 영상에서 03:00에 Notes 필드에 포커스만 주고 공백을 입력합니다. 03:24에 첫 비공백 글자를 입력한 뒤 재생/seek로 04:12로 이동해 저장합니다. 타임스탬프 버튼은 **3:24**, 클릭하면 204초로 이동해야 합니다.
4. 다른 새 초안은 첫 시각을 캡처한 뒤 입력 중 패널 닫기/열기·새로고침을 수행합니다(쓰기 완료를 기다림). 영상 B로 이동했다가 A로 돌아와 다른 위치에서 저장해도 A의 최초 제목/시각을 유지해야 합니다. 전체 삭제 후 다시 입력하면 새 시각이어야 합니다. 기존 메모의 시각/내용도 확인합니다.
5. 1~2분 영상을 1배속으로 충분히 재생해 종료 성찰이 한 번 뜨는지 확인합니다. 5초 이전 저장, 5초 후 기록 없이 건너뛰기, 자동재생 중 다음 영상 정지/복구를 다시 확인합니다. 사용자에게 확인된 HOTFIX-002 동작의 회귀 확인 항목입니다.

자동 DOM 테스트는 실제 키 입력 삽입이나 운영 YouTube의 리스너 등록 순서를 검증하지 않습니다. 설치 커밋·Chrome 버전과 각 항목의 통과/실패/미실행을 구분해서 기록하세요.

## UI-001: 액션 바 PAUSE Note와 패널

기준은 BUGFIX-001 `0bd7b421128515dffbdbe34363ad20fc751b3466`이며 UI 작업 브랜치는 `feature/pause-notes-ui`입니다. 사용자 Chrome 보고상 Space·숫자·한글·최초 입력 시각·종료 성찰은 정상입니다. 이 UI 빌드의 실제 Chrome 배치 및 전체화면·광고·자동재생·다중 탭은 별도 검증 대기입니다.

### 배치 구조와 근거

`src/action-entry.ts`는 watch의 기존 액션 그룹에 PAUSE 전용 Shadow DOM 캡슐 버튼 하나를 추가합니다. `Ⅱ PAUSE Note`와 확장 프로그램 tooltip으로 브랜드를 구분하고 기존 Notes 패널의 열림 상태만 토글합니다. 데이터/패널은 새로 만들지 않습니다. 버튼 자체는 별도 스타일 경계를 사용하며, 입력창은 기존 Shadow DOM에 그대로 있어 BUGFIX-001 격리를 유지합니다.

삽입 후보는 다음 순서입니다. 이는 watch metadata의 actions/menu 구조를 가정한 **호환성 후보**이며, 이 환경에서 실제 YouTube DOM을 확인한 셀렉터라고 주장하지 않습니다. 환경에 브라우저 도구가 없고 YouTube 도메인도 허용 목록에 없어 라이브 DOM 확인은 수행하지 못했습니다.

1. `ytd-watch-metadata #actions #top-level-buttons-computed`: 좋아요/공유 등의 최상위 버튼 그룹으로 범위를 제한합니다.
2. `ytd-watch-metadata #actions-inner #top-level-buttons-computed`: actions-inner 래퍼 변형을 허용합니다.
3. `ytd-watch-flexy #above-the-fold #actions ytd-menu-renderer #top-level-buttons-computed`: watch의 상단 metadata/menu 변형에 한정합니다.

Shorts/홈/기타 페이지는 주입 대상이 아닙니다. URL, 화면 너비, 실제 요소 크기·숨김·오버플로를 확인하고 성공한 동안 FAB를 숨깁니다. 840px 미만, 타깃 미발견/숨김, 가로 영역 초과 시 action 버튼은 제거 또는 숨김/비활성하고 기존 FAB를 제공합니다. 제한된 자리의 숨긴 버튼은 absolute로 배제해 다른 버튼의 공간을 점유하지 않습니다. 현재 판정은 보수적이며 공간이 있어도 FAB가 나올 수 있습니다.

구조 변경 감지는 MutationObserver 하나에서 관련 watch/metadata 노드 변경을 필터링하고 requestAnimationFrame으로 프레임당 한 번으로 합칩니다. 크기는 ResizeObserver와 window resize로 재평가합니다. 반복 폴링은 하지 않습니다. SPA 완료/popstate, 액션 바 재생성에서 같은 호스트를 이동하고 dispose 시 observer·예약 frame·리스너·호스트를 제거합니다. 기존 재생 추적기의 observer/정책은 변경하지 않습니다.

패널은 중립 배경·간격·명시적인 focus ring·고대비 모드·좁은 창 폭을 지원하며 YouTube `html[dark]` 속성을 따라갑니다. 색·레이아웃 테스트는 DOM 모의 검사이며 실제 픽셀/대비 측정이나 YouTube 테마 검증은 아닙니다.

## Material 색상과 영상별 종료 성찰 제외

현재 Notes/성찰/액션 버튼은 회색 표면과 파란색 강조를 쓰는 Material-inspired 스타일입니다. Google 공식 UI 또는 Material 컴포넌트 라이브러리를 사용하는 것은 아니며, PAUSE 이름과 YouTube 캡슐 버튼 형태를 유지합니다. 콘텐츠는 YouTube의 라이트/다크 속성을, popup은 시스템 색상 모드를 따릅니다. 외부 폰트나 추가 API는 사용하지 않습니다. Notes 헤더 썸네일은 아래 설명처럼 YouTube 이미지 CDN에서 불러옵니다.

Notes 패널의 **이 영상의 종료 성찰**에서 `사용`, `음악 · 제외`, `ASMR · 제외`, `광고 · 제외`, `인강 · 제외`를 선택합니다. 제외 사유는 사용자가 직접 지정하며, 해당 영상 ID에만 적용됩니다. 자동 카테고리 판정이나 제목 키워드 필터가 아닙니다. Notes 버튼과 초안/메모/타임스탬프는 계속 사용할 수 있습니다. `사용`으로 되돌리면 이후 시청에 성찰을 다시 적용합니다. 이미 종료 판정된 영상은 탭 수명당 한 번 정책 때문에 새로고침 후 재시험하세요.

`광고 · 제외`는 광고 자체를 watch 영상으로 보고 있을 때 그 영상을 제외하는 선택입니다. 본 영상 안의 중간 광고를 자동 감지하거나, 중간 광고가 있다는 이유로 본 영상 전체를 자동 제외하지 않습니다. 기존 광고 시간 혼입 한계도 자동 해결된 것으로 간주하지 않습니다.

제외는 `chrome.storage.local`의 `pause:v1:exclusion:<videoId>`에 저장하고 해제 시 null로 비활성화합니다. 기존 기록을 변환하거나 삭제하지 않습니다. 다른 탭에서 바꾼 설정도 저장소 이벤트로 읽으며 동일 영상 설정은 마지막 저장 우선입니다. 저장 실패 시 이전 설정으로 복구하고 오류를 표시합니다. 전체 PAUSE 사용 설정이 꺼져 있으면 Notes도 꺼지는 기존 정책은 유지됩니다.

수동 확인: 두 테마에서 중립색/대비/포커스를 확인하고, 음악 영상을 제외한 뒤 유효 시청 종료 시 Notes는 남고 성찰만 생략되는지 확인하세요. 같은 영상에서 메모 저장/타임스탬프 이동, 새로고침 후 제외 유지, 해제 후 새 시청, 다음 일반 영상의 5초 성찰을 각각 확인합니다. 선택창의 숫자/방향키가 YouTube 탐색을 유발하지 않는지도 확인하세요. 실제 YouTube에서의 이번 변경은 별도 검증 대상입니다.

개발 환경의 Chromium에서 합성 watch 페이지 + mock chrome.storage를 사용해 Notes 패널/선택지 5개와 라이트·다크 렌더링을 확인했습니다. 이것은 실제 YouTube DOM, 확장 프로그램 설치 상태 또는 사용자 영상 종료에 대한 검증 결과가 아닙니다.

### 액션 버튼 치수 맞춤

액션 버튼의 별도 테두리를 없애고 24px SVG 아이콘으로 정렬했습니다. 같은 액션 그룹의 보이는 native 버튼(최대 12개 후보)에서 높이·글꼴·굵기·배경·글자색을 읽어 PAUSE 자체 CSS 변수에 적용합니다. YouTube의 클래스나 클릭 동작을 복제하지 않습니다. 대상이 없거나 배경이 투명하면 36px/14px/500과 YouTube 중립색으로 대체합니다. 부모 gap이 있으면 추가 여백을 중복하지 않습니다. 사용자 스크린샷을 근거로 한 수정이며 실제 사용자 페이지에서의 픽셀 일치는 재확인이 필요합니다.


### Notes 썸네일 헤더

직접 열어 쓰는 Notes 카드의 닫기는 우측 상단 X 아이콘(접근성 이름: 메모 패널 닫기)입니다. 상단 영상 썸네일 위로 아래 방향의 투명→현재 카드 배경색 그라데이션을 겹치며 라이트/다크 전환에도 같은 색으로 이어집니다. 썸네일은 장식 이미지라 스크린리더에서 중복 낭독하지 않습니다. SPA 영상 ID가 바뀌면 헤더 이미지와 오류 상태도 교체됩니다. 로드 실패 시 중립색 배경과 제목·닫기를 유지합니다. 닫아도 초안/최초 입력 시각은 지우지 않습니다. 자동 종료 성찰의 닫기/5초 정책은 변경하지 않습니다.

Notes 패널을 열면 `https://i.ytimg.com/vi/<videoId>/hqdefault.jpg`로 이미지 요청이 발생합니다. 영상 ID가 해당 YouTube CDN에 전달되지만 메모나 영상 제목을 URL/요청 본문에 포함하지 않으며 referrer는 보내지 않습니다. 별도 API 키나 Chrome 권한은 추가하지 않습니다. 네트워크/CSP 차단 시 이미지 없이 사용할 수 있습니다. 실제 YouTube에서 X 클릭·키보드 접근·스크롤·두 테마 그라데이션·다른 영상 이동을 재확인하세요.

## 추천 열 Notes · 확장 프로그램 설정

최신 UI에서는 Notes 카드의 제외 드롭다운을 제거했습니다. **도구 모음 PAUSE → 설정 열기**, 또는 `chrome://extensions`의 PAUSE 확장 프로그램 옵션으로 별도 설정 탭을 엽니다. popup에서 열면 활성 watch 탭의 content script에 현재 영상 ID만 요청해 선택합니다. tabs/activeTab 권한은 추가하지 않습니다. 다른 페이지에서는 기록된 영상/제외 영상 목록에서 선택합니다.

설정 페이지의 음악·ASMR·광고·인강은 **영상별 제외 사유 체크박스**로 여러 개를 함께 선택할 수 있습니다. 자동 분류나 중간 광고 감지는 아닙니다. 모두 해제하면 제외를 취소합니다. 기존 단일 사유 데이터는 그대로 읽고 새 다중 사유는 배열로 저장합니다. 일반 PAUSE 켜기/성찰 켜기는 popup의 기존 설정을 유지합니다.

넓은 watch 화면에서는 추천 열의 `ytd-watch-flexy #secondary #secondary-inner`, `ytd-watch-flexy #secondary-inner`, `ytd-watch-flexy #secondary` 순서로 보이는 폭 280px 이상 영역을 찾아 Notes 호스트를 첫 자식으로 배치합니다. 1000px 미만 창이나 추천 열 미발견/숨김에서는 기존 카드 접근을 유지합니다. 추천 열을 찾아도 자동으로 열지 않습니다. 사용자가 Notes 버튼을 눌러 열고, X로 닫은 뒤 다시 열 수 있습니다. React portal로 같은 앱의 초안·캡처·저장 상태를 재사용하며 새 데이터 인스턴스는 만들지 않습니다. 추천 열 DOM 교체/항목 선삽입/SPA/resize를 감지해 한 frame으로 합쳐 재배치합니다. 삽입 예외는 기존 카드로 복구합니다. 전체화면과 YouTube 실험 DOM에서의 실제 배치는 재확인 대상입니다.

종료 성찰은 원본 영상 ID의 썸네일과 같은 그라데이션 헤더를 사용합니다. **성찰 헤더에는 X를 추가하지 않았으며 즉시 저장·5초 이후 건너뛰기 정책을 유지**합니다. 추천 열 Notes와 성찰은 별도 DOM 영역에 표시됩니다. 일반 모드의 카드/입력창/구분선/버튼 테두리를 제거했으며 키보드 focus ring과 고대비 모드의 필수 구분은 유지합니다.

검증: 설정의 다중 체크·해제·기존 사유 호환, 설정 열기 메시지, 추천 열 최상단/DOM 교체/좁은 창 전환/단일 패널/초안 보존/입력 키 격리/성찰 썸네일을 자동 검사합니다. 실제 Chrome에서는 옵션 페이지 열기, 현재 영상 선택, 체크 후 종료 성찰 생략과 Notes 유지, 추천 열 상단 배치·창 크기·뒤로 가기·다른 영상 이동, 두 테마의 테두리 제거, 성찰 썸네일 및 5초 정책을 재확인하세요. 실제 YouTube 검증을 자동 DOM 테스트와 혼동하지 마세요.

로컬 Chromium에서 합성 추천 열의 Notes 상단 배치(라이트/다크)와 빌드된 options.html의 체크박스 4개 및 다중 체크 표시를 확인했습니다. chrome.storage는 mock이며 실제 YouTube·확장 프로그램 설치 검증 결과는 아닙니다.


### Notes 열기 애니메이션

Notes는 기본 닫힘입니다. 버튼을 누를 때만 추천 열 상단의 높이가 약 480ms 동안 확장돼 아래 영상을 밀어내고, 카드가 약 520ms의 작은 스프링 모션으로 나타납니다. 카드 아래 추천 목록에는 클릭을 가로채지 않는 약한 그라데이션 디밍을 겹칩니다. 닫을 때 높이/디밍이 줄어들며 초안·최초 시각은 앱 상태에 남습니다. 빠르게 닫았다 열어도 이전 종료 타이머는 취소합니다. 닫는 동안 입력 영역은 inert/aria-hidden으로 포커스와 스크린리더에서 제외합니다. 모션 줄이기 환경에서는 전환과 스프링을 생략합니다. 종료 성찰의 자동 표시와 5초 정책은 바꾸지 않습니다. 실제 YouTube에서 아래 목록 이동, 디밍, 클릭 방해 여부, 빠른 연속 토글과 좁은 창 전환을 재확인하세요.

로컬 Chromium 합성 추천 열에서 기본 Notes 높이 0 → 클릭 후 확장 → 닫기 후 0 복구와 추천 목록의 실제 Y 좌표 이동을 측정했습니다. 모션 줄이기에서는 transition 0s/animation none을 확인했습니다. 실제 YouTube에서 같은 결과를 확인한 것은 아닙니다.

### 전체화면 Notes

YouTube 플레이어가 DOM 전체화면으로 들어가면 기존 PAUSE 앱 호스트를 fullscreenElement 안으로 옮깁니다. React 앱/초안/타임스탬프 상태는 새로 만들지 않습니다. 하단 `.ytp-right-controls`에서 전체화면 버튼 앞에 PAUSE Notes 아이콘을 넣고, 클릭 시 우하단 카드로 열립니다. 컨트롤 영역이 없으면 FAB를 남깁니다. 전체화면에서는 추천 열 삽입을 중단하고, 나가면 기존 배치와 초안 상태를 복구합니다. 성찰도 같은 전체화면 호스트 안에 표시하며 5초 정책을 유지합니다.

플레이어 컨테이너가 아닌 `<video>` 자체의 네이티브 전체화면은 오버레이를 올릴 수 없어 지원 대상으로 주장하지 않습니다. YouTube 컨트롤 DOM 실험/브라우저별 동작은 수동 검증이 필요합니다. 실제 Chrome에서 전체화면 진입→PAUSE 아이콘→Space/숫자/IME 입력→초안 유지하며 나가기/재진입→메모 저장, 종료 성찰 표시/5초 건너뛰기를 확인하세요. 자동 테스트의 fullscreenElement 모의는 실제 브라우저 전체화면 검증을 대체하지 않습니다.

이 환경의 headless Chromium 실제 Fullscreen API 요청은 Promise가 완료되지 않고 fullscreenElement도 설정되지 않아 실제 진입을 검증하지 못했습니다. 전체화면 배치/상태 유지 테스트는 jsdom 모의 결과이며, 설치한 데스크톱 Chrome YouTube에서 검증 대기입니다.

### 애니메이션 누락 / 전체화면 FAB 겹침 보완

추천 열에 붙지 못해 일반 카드로 열리는 경로에 진입 애니메이션이 누락된 것을 확인해 동일한 spring keyframe을 연결했습니다. 추천 열의 높이 전환과 모션 줄이기 정책은 유지합니다. 움직임 줄이기가 켜지면 의도적으로 애니메이션을 생략합니다(`matchMedia('(prefers-reduced-motion: reduce)').matches`로 확인 가능).

전체화면은 Fullscreen API 외에 `#movie_player.ytp-fullscreen`, `.html5-video-player.ytp-fullscreen`, `ytd-watch-flexy[fullscreen] #movie_player` 상태도 인식합니다. 기본 전체화면 버튼의 부모 행을 우선 사용하고, 보이는 right-controls/chrome-controls/chrome-bottom으로 대체합니다. 컨트롤을 못 찾거나 숨겨져 있으면 하단의 큰 텍스트 FAB 대신 **상단 우측 44px 아이콘**만 표시해 하단 조작계를 덮지 않습니다. 크기나 화면 비율만으로 전체화면을 추측하지 않습니다. 사용자 스크린샷의 실제 DOM은 아직 확보하지 못했으므로 해당 환경의 정확한 컨트롤 미탐지 원인은 미확정입니다.

로컬 Chromium 합성 화면에서 일반 카드의 중간 프레임(transform/opacity)→최종 프레임 변화, YouTube fullscreen 클래스 시뮬레이션의 컨트롤 아이콘 삽입, 컨트롤 제거 후 상단 아이콘 크기/위치를 측정했습니다. 실제 YouTube 전체화면 검증을 대체하지 않습니다. 새 빌드의 PAUSE-BUILD.json 커밋을 확인하고 확장 프로그램·YouTube 탭을 둘 다 새로고침한 뒤 일반/추천 열/전체화면에서 열기를 재확인하세요.
