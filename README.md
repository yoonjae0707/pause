# PAUSE

**넘기기 전에, 남겨보세요.** YouTube 롱폼 영상을 시청하고 메모·성찰을 기기에 저장하는 Chrome Manifest V3 확장 프로그램입니다. 외부 서버로 기록을 전송하지 않습니다.

## 현재 준비 상태

Task 001의 기반 구현에 Task 002 안정화를 추가했습니다. 자동 테스트와 빌드는 실행했지만, **실제 데스크톱 Chrome + YouTube 수동 검증은 모두 검증 대기**입니다. 자동 테스트의 jsdom 영상·저장소 mock 결과를 Chrome 통과로 해석하지 마세요. 절차와 기록 양식은 [10분 수동 검증 가이드](docs/manual-chrome.md)에 있습니다.

## 빌드와 설치 산출물

필요 도구: Node.js 22.12+ 또는 24 LTS, npm, ZIP 포장 시 Python 3.

```sh
npm ci
npm test
npm run build
npm run package:chrome
```

`build`는 타입 검사와 popup/content script 프로덕션 빌드입니다. `package:chrome`은 다시 빌드한 뒤 다음 파일을 생성하고 ZIP 무결성과 manifest의 참조 파일을 확인합니다.

- `dist/`: Chrome에 로드할 폴더. 바로 아래에 `manifest.json`, `content.js`, `popup.html`, `assets/`가 있습니다.
- `dist/PAUSE-BUILD.json`: 빌드 커밋, 미커밋 변경 여부, 빌드 시각, Node 버전, lockfile 해시. 검증한 버전 식별용이며 메모/비밀값은 포함하지 않습니다.
- `artifacts/pause-chrome-0.1.0-task002.zip`: **ZIP 바로 안에 manifest.json이 있는** 설치 패키지.
- `artifacts/SHA256SUMS`: 위 ZIP의 SHA-256.

### PC로 가져오는 방법

클라우드의 `/workspace/pause/dist` 또는 `/workspace/...zip` 경로는 **사용자 PC에서 열 수 있는 다운로드 URL이 아닙니다**. 이 문서의 로컬 파일 링크도 배포 링크가 아닙니다. GitHub 소스의 **Code → Download ZIP**에는 빌드 산출물이 없습니다.

권장 방법은 GitHub Actions 아티팩트입니다. 이 브랜치의 `.github/workflows/chrome-build.yml`은 push/PR에서 테스트와 빌드를 실행하고 `dist/`를 `pause-chrome-task002`라는 아티팩트로 14일간 보관합니다. 릴리스나 운영 배포는 만들지 않습니다.

1. GitHub에서 이 저장소의 **Actions → Chrome validation build**를 엽니다. 작업 브랜치 `feature/pause-longform-mvp`와 최신 커밋의 실행을 선택합니다.
2. 테스트와 빌드, 업로드 단계가 성공했는지 확인합니다. **성공한 원격 실행을 확인하기 전에는 다운로드 가능한 아티팩트가 있다고 간주하지 마세요.** Actions 비활성화·워크플로 파일 push 권한 부족·용량 제한 시 아티팩트가 생기지 않을 수 있습니다. `workflow_dispatch` 버튼은 워크플로가 기본 브랜치에 없으면 표시되지 않을 수 있습니다.
3. 실행 상세의 **Artifacts → pause-chrome-task002**를 클릭해 `pause-chrome-task002.zip`을 PC에 다운로드합니다. GitHub 로그인과 저장소 읽기 권한이 필요합니다. 만료 시 새 push로 다시 빌드하거나 아래 PC 빌드를 사용합니다.
4. 예를 들어 PC의 `Downloads/PAUSE/task002/`에 압축을 풉니다. **그 폴더 바로 아래에 `manifest.json`이 있는지 확인**합니다. GitHub Actions ZIP은 dist 내용 자체를 담으므로 내부 ZIP을 다시 풀 필요가 없습니다.
5. 클라우드 파일 다운로드 기능이 별도로 제공된다면 `artifacts/pause-chrome-0.1.0-task002.zip`을 내려받아 같은 방식으로 압축을 풀 수 있습니다. 이 작업 환경에서는 파일 업로드/다운로드 URL 발급 도구가 제공되지 않아 해당 링크를 발급하지 않았습니다.

원격 Actions 사용이 막힌 경우, PC에서 GitHub 소스를 받아 직접 빌드할 수 있습니다. 공개 릴리스 승인은 필요하지 않습니다.

```sh
git clone --branch feature/pause-longform-mvp https://github.com/yoonjae0707/pause.git
cd pause
npm ci
npm test
npm run build
```

이 경우 PC의 `pause/dist/`를 사용합니다. Python이 없어도 `build`까지는 가능합니다.

### 데스크톱 Chrome 설치와 설치 확인

1. ZIP이라면 먼저 압축을 풉니다. Chrome은 ZIP 파일을 직접 로드하지 않습니다. 로드한 폴더는 삭제하거나 이동하지 마세요.
2. Chrome 주소창에 `chrome://extensions`를 입력하고 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드**를 눌러 `manifest.json`이 바로 있는 폴더를 선택합니다. Actions 다운로드 예시는 `Downloads/PAUSE/task002/`, PC 빌드는 `pause/dist/`입니다. 소스 루트나 `assets/`를 선택하지 마세요.
4. 목록에서 PAUSE 0.1.0이 활성 상태이고 오류가 없는지 확인합니다. 도구 모음의 확장 프로그램 메뉴에서 PAUSE popup을 열어 두 설정과 기록 수를 확인합니다.
5. 이미 열려 있던 `https://www.youtube.com/watch?v=...` 탭을 새로고침합니다. PAUSE 사용을 켠 상태에서 `PAUSE Notes` 버튼이 보이는지 확인합니다.
6. 새 빌드로 교체할 때 기존 확장 프로그램의 **새로고침**을 누르고 YouTube 탭도 새로고침합니다. 기록을 유지하려면 확장 프로그램을 삭제해 재설치하지 마세요. 설치한 폴더의 `PAUSE-BUILD.json` 커밋을 기록합니다.

`npm run dev`는 popup UI 개발용입니다. 확장 프로그램의 빌드/설치와 YouTube 테스트를 대체하지 않습니다.

## 시청·성찰 정책

- 추적/UI는 `/watch?v=...`에서 활성화합니다. 홈 → watch SPA 이동을 위해 content script 주입 대상은 `https://www.youtube.com/*`입니다.
- **벽시계 기준** 실제 재생 시간이 30초 이상이며 영상 길이의 70% 이상일 때 종료 성찰을 표시합니다. 100초 영상을 2배속으로 50초 시청하면 70초 기준을 충족하지 않습니다. 고유 구간 커버리지 대신 재시청 시간도 누적합니다.
- seek와 속도에 맞지 않는 위치 도약은 제외합니다. SPA 이동 중 이벤트를 해제하고, video 교체/소스 로드에서 기준점을 초기화합니다. 같은 바인딩의 이벤트 리스너를 중복 등록하지 않습니다. 성찰 중에는 시청 시간을 누적하지 않습니다.
- 동일 영상의 종료 개입은 탭의 content script 수명 동안 한 번입니다. 새로고침 시 시청 누적/개입 상태만 초기화되고 저장 메모/초안은 남습니다. 라이브·무한 길이는 종료 성찰 대상이 아닙니다.
- 성찰은 즉시 저장 가능하며, 기록 없이 건너뛰기는 5초 뒤 가능합니다. 불이익이 없습니다.
- 개입 중 일반 클릭으로 요청한 동일 사이트 watch/shorts 링크 한 개를 완료 후 이동합니다. 수정키/새 탭 이동은 가로채지 않습니다. 개입이 일시정지시킨 다른 영상이 여전히 현재 영상이면 완료 후 재개를 시도합니다. 이미 일시정지된 영상이나 종료된 원본을 임의로 재생하지 않습니다. 명시적인 링크 요청이 있으면 그 이동을 우선합니다. 브라우저가 재개를 거절하면 직접 재생 버튼을 눌러야 합니다.

## 데이터·동시 편집·권한

`chrome.storage.local`의 `pause:v1:` 개별 키를 사용합니다. `VideoRecord`, `TimestampNote`, `Reflection`, `ShortsSession`, `UserSettings` 모델이 있습니다. 쇼츠 UI, Library, 서버, 로그인, AI, 휴식 알림은 없습니다. 권한은 `storage` 하나입니다.

- 메모 저장 버튼을 누른 시점의 영상 ID·제목·URL·재생 시각을 캡처합니다. 저장 중 SPA 이동이 발생해도 다른 영상 제목으로 기록하지 않습니다.
- 저장 메모·영상 메타데이터·초안 비우기를 하나의 storage.set 요청으로 보냅니다. 실패 시 초안을 남기고 오류를 안내합니다. 별도 트랜잭션/분산 잠금을 구현한 것은 아닙니다.
- **동일 영상 초안을 여러 탭에서 편집하면 마지막 저장 우선이며, 다른 탭의 초안을 덮어쓸 수 있습니다.** 입력 중인 다른 탭의 로컬 UI는 자동으로 병합/갱신하지 않습니다. 한 탭에서 메모를 저장하며 초안을 비우는 것도 마지막 쓰기입니다. 탭마다 다른 내용이 있으면 각자 저장 메모로 확정한 뒤 이동하세요. 동일 영상 메타데이터와 설정에도 마지막 저장 우선이 적용됩니다. 서로 다른 저장 메모는 고유 ID를 사용합니다.
- 초안 쓰기는 비동기입니다. 입력 직후 즉시 새로고침/탭 종료하면 미완료 쓰기가 유실될 수 있습니다. 중요한 내용은 **메모 저장 후 목록에 표시된 것을 확인**하세요. 저장 실패/용량 초과 시 내용을 복사해 보관하고 다시 시도하세요.
- 확장 프로그램 삭제 시 기록도 삭제됩니다. 현재 내보내기/백업/삭제 관리 UI는 없습니다.

## 알려진 한계와 광고 처리 결정

YouTube 내부 자동재생 예약, 키보드 이동, 브라우저 뒤로/앞으로 및 전체 페이지 이동을 모두 차단하지 않습니다. 다음 URL로 이미 넘어갔을 수 있으며 새 video를 일시정지·재개하는 방식은 최선 노력입니다. 전체 페이지 탐색은 메모리에 있는 성찰/보류 이동 요청을 잃을 수 있습니다. 브라우저 타이머 제한과 DOM 변경에도 영향을 받습니다. 전체화면은 YouTube 플레이어 밖의 오버레이가 보이지 않을 수 있으므로 직접 확인해야 합니다.

**HTML5 video 이벤트만으로 광고를 신뢰성 있게 구분할 수 없습니다.** 현재 구현은 광고를 제외한다고 주장하지 않습니다. `#movie_player.ad-showing` 같은 내부 클래스는 진단 힌트일 뿐 안정적인 공개 API가 아니므로 추측으로 시청 시간을 빼지 않습니다. 광고가 같은 video/영상 ID를 사용하면 시간 누적 또는 광고 ended가 성찰 조건에 영향을 줄 수 있습니다. 소스 교체 시 기준점 초기화는 이 문제 전체를 해결하지 않습니다.

수동 검증에서는 광고 유무를 반드시 기록하고, 광고가 없는 영상 테스트와 분리하세요. 광고가 나타나지 않으면 그 항목은 통과가 아니라 검증 대기입니다. 광고 환경의 오개입이 확인되면 성찰 설정을 끄고 Notes만 사용하는 것이 현재 대안입니다. 신뢰할 수 있는 식별 근거를 확보하기 전까지 공개 준비 완료로 판단하지 않습니다.

## HOTFIX-002: 종료 성찰 진단과 Chrome 재시험

진단은 기본 꺼짐입니다. **popup → 개발용 진단 로그**를 켠 뒤 YouTube 개발자 도구 Console에서 **Info 표시 + Preserve log(로그 보존)**를 켜고 `[PAUSE diagnostic]`으로 필터링하세요. 영상 제목·메모·계정·비밀값은 기록하지 않습니다. 영상 ID와 재생 수치는 진단에 포함됩니다. 테스트 후 popup에서 진단을 끄세요. 로그는 저장소/서버에 수집하지 않고 해당 탭 콘솔에만 출력합니다.

1. 설치는 위 Actions 아티팩트 절차를 사용합니다. 빌드 번호는 여전히 0.1.0이므로 `PAUSE-BUILD.json`의 커밋을 확인하세요. 확장 프로그램과 YouTube 탭을 모두 새로고침합니다. 원격 Actions 성공/아티팩트 생성은 이 작업에서 확인하지 못했습니다.
2. 자동재생을 끄고, 광고 없는 `/watch`의 **1~2분 영상**을 새로고침 후 **1배속·탭 활성·seek 없이 처음부터 끝까지** 재생합니다. PAUSE와 종료 성찰 설정이 켜져 있어야 합니다. 메모 초안을 먼저 입력해 종료 후에도 유지되는지 확인하세요.
3. 정상 로그 흐름은 `sample`의 watched 증가 → `ended`의 `reason: eligible` → `intervention-start` → `overlay-mounted`입니다. ratio는 벽시계 누적/영상 길이이며 최소 0.7, watched는 최소 30초여야 합니다. 화면은 한 번만 나타나고, 5초 이전 저장 가능/건너뛰기 불가, 5초 후 기록 없이 건너뛰기 가능해야 성공입니다.
4. 새로고침해 다시 누적을 초기화하고 자동재생을 켠 상태/재생목록에서 반복합니다. `spa-start`, `binding-boundary`가 `ended`보다 먼저 오는지 확인하세요. 원본 ID로 성찰이 뜨고 다음 영상이 정지되는지 확인합니다. 완료 후 다음 영상 재생 또는 수동 재생이 가능해야 합니다. 이 경로를 실제로 보지 못했으면 검증 대기입니다.
5. 광고가 보이면 `adHint`와 `source-reset` 전후 watched/duration을 함께 기록하세요. 광고 힌트는 추정용이며 광고 시간 제외 기능이 아닙니다. 광고 오개입 또는 종료 누락은 별도로 실패 기록합니다. 비활성 탭/버퍼링/seek 시험은 기본 정상 종료 시험과 분리하세요.
6. Console의 PAUSE 로그 행만 선택해 복사합니다. **전체 Console/HAR/페이지 객체를 통째로 공유하지 마세요.** 진단 시작부터 종료/SPA 이후까지의 JSON 행과 Chrome 버전, 빌드 커밋, 자동재생/광고 여부를 함께 전달하세요.

해석:

- `under-30s` / `under-70-percent`: 정책 미달. sample의 watched와 seeking/source-reset을 확인합니다. 버퍼링 중 시간이 누적되지 않는 것은 정상입니다. 2배속 영상은 길이의 70% 벽시계 조건을 충족하지 못할 수 있습니다.
- `unknown-duration`: 메타데이터가 없거나 라이브/무한 길이입니다.
- `not-at-end`: 이동 시 종료 증거가 부족합니다. 충분히 봤다는 이유만으로 중도 이동을 종료로 간주하지 않습니다.
- `suspended` / `already-handled`: 기존 개입 중이거나 이 탭에서 이미 처리한 영상입니다. 새로고침 후 별도 시험하세요.
- `intervention-rejected`: 설정 비활성/기존 overlay 활성. 거부 시 처리 완료를 확정하지 않도록 수정했습니다.
- `intervention-start`는 있지만 `overlay-mounted`가 없음: React 표시 경로 실패 가능성. Console 오류를 함께 기록하세요.
- `overlay-mounted`는 있지만 화면이 안 보임: 전체화면/표시 레이어 문제 가능성. 전체화면을 나와 확인하세요. mount 로그만으로 실제 표시 통과를 판정하지 않습니다.
- 종료 로그 없이 `spa-start`/`binding-change`만 있음: YouTube가 ended 전에 이동했거나 요소를 교체했을 가능성. 이전 sample의 position/duration을 확인하세요.

확인된 코드 결함은 SPA 전환/요소 해제 시 원본 종료 확인 누락, 그리고 UI가 거부한 개입까지 handled 처리하는 경로입니다. 사용자 환경에서의 원인은 아직 미확정입니다. 종료 경합 보완은 원본의 `ended` 또는 **마지막 관측 위치가 끝에서 0.25초 이내이고 seeking 중이 아닌 경우**에만 적용합니다. 30초·70% 기준은 변경하지 않았습니다. 끝에서 0.25초 이내의 수동 이동을 종료로 추정할 가능성이 있고, 더 이른 자동 전환이나 sample 자체가 없는 경우는 여전히 놓칠 수 있습니다. 광고 식별은 공개 API 없이 확정할 수 없어 추측으로 누적 시간을 제외하지 않습니다.
